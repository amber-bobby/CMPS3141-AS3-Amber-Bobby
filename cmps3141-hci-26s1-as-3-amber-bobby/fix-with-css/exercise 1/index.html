Fixing the Web with CSS

Three usability improvements made purely with CSS, one each for efficiency, learnability, and safety.

Contents

  1. Reddit — bigger vote targets (Efficiency)
  2. YouTube — visible label on Dislike (Learnability)
  3. Wikipedia — prominent login/create-account links (Safety)

1. Reddit — Bigger Vote Targets

Website & page: reddit.com, any post or comment thread (upvote/downvote controls).

The CSS

[data-action-bar-action="upvote"],
[data-action-bar-action="downvote"] {
  --size-button-sm-h: 40px;
  padding: 8px;
}

[data-action-bar-action="upvote"] svg,
[data-action-bar-action="downvote"] svg {
  width: 22px;
  height: 22px;
}

Usability dimension(s)

Efficiency.

Why this helps

The original vote buttons render their 16px icon inside a small, zero-padding square — a small, precise target for the single most frequent action on the site. By Fitts's Law, the time it takes to move to and click a target grows as the target shrinks, so enlarging both the icon and the clickable padding around it reduces the time and precision needed to vote correctly. No !important was needed: the button's height is set inline via a CSS custom property (style="height: var(--size-button-sm-h)"), so redefining that variable on the element changes what the inline declaration resolves to, rather than fighting it; the SVG's width/height are HTML presentation attributes, which sit at the very bottom of the cascade and are overridden by any CSS rule.

2. YouTube — Visible Label on the Dislike Button

Website & page: youtube.com, any video watch page (the action row under the player, next to Like/Share/Ask/Save).

The CSS

[aria-label="Dislike this video"] {
  display: inline-flex;
  align-items: center;
  padding-right: 12px;
}

[aria-label="Dislike this video"]::after {
  content: "Dislike";
  margin-left: 6px;
  font-size: 14px;
  font-weight: 500;
}

Usability dimension(s)

Learnability.

Why this helps

Every other button in this action row carries a visible text label: Like shows its running count, and Share, Ask, and Save each show their own word right next to the icon. Dislike is the sole exception — it renders as a bare icon with only an aria-label for screen readers, so a sighted user has to already recognize the thumbs-down convention to know what it does. Adding a generated text label with ::after brings Dislike in line with its neighbors, replacing a hidden affordance with an explicit signifier instead of relying on the user's prior familiarity with the icon. No !important is needed, since the button's own style attribute is empty.

3. Wikipedia — Prominent Login / Create-Account Links

Website & page: en.wikipedia.org, the edit page for any article, reached while logged out (e.g. /w/index.php?title=ANY_ARTICLE&action=edit).

The CSS

.mw-anon-edit-warning a[href*="UserLogin"],
.mw-anon-edit-warning a[href*="CreateAccount"] {
  display: inline-block;
  background-color: #3366cc;
  color: white;
  padding: 6px 14px;
  border-radius: 4px;
  text-decoration: none;
  font-weight: 600;
  margin: 4px 4px 0 0;
}

Usability dimension(s)

Safety.

Why this helps

When editing while logged out, Wikipedia now assigns a temporary account and describes it only vaguely as offering “a very basic level of privacy,” without spelling out what that means. The message does give two ways to avoid that tradeoff — logging in or creating an account — but both are rendered as plain inline text links, visually indistinguishable from the rest of the paragraph. This is a poor signifier: the one actionable, protective choice in the message is easy to skim right past. Styling those two links as clear, high-contrast buttons increases their visual salience, making the safer, more deliberate option the one that's easiest to notice and act on. No !important is needed, since neither link carries a conflicting inline style attribute.
